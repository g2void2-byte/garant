# Политика безопасности / Security Policy

`garant` — это эскроу-сервис в форме Telegram Mini App, оперирующий
средствами пользователей. Мы серьёзно относимся к любым отчётам об
уязвимостях, влияющих на сохранность пользовательских балансов,
аутентификацию, целостность сделок или приватность данных.

## Поддерживаемые ветки / Supported branches

| Ветка / Branch | Статус / Status |
| --- | --- |
| `devin/1778660441-fresh-rewrite-sqlalchemy` (default) | Активно поддерживается |
| Любая другая `devin/…` | Best-effort, по предварительному согласованию |

Релизных тегов сейчас нет; уязвимости фиксятся в default-ветке и
автоматически попадают в следующий деплой.

## Как сообщить об уязвимости / How to report

**Не открывайте публичный GitHub Issue / Pull Request.** Используйте
любой из следующих приватных каналов:

1. **GitHub Private Vulnerability Reporting** —
   <https://github.com/g2void2-byte/garant/security/advisories/new>
   (предпочтительный канал — даёт нам трекинг, CVE-ID и
   приватное сотрудничество над патчем).
2. **Telegram DM мейнтейнеру** — контактные данные привязаны к
   git commit signature default-ветки.

В отчёте укажите:

* затрагиваемую версию (коммит-SHA default-ветки);
* пошаговый сценарий воспроизведения (curl / Playwright / скриншоты);
* предполагаемый impact (CIA-классификация: confidentiality,
  integrity, availability);
* предлагаемый CVSS-вектор, если есть.

## SLA

| Этап | Целевое время |
| --- | --- |
| Подтверждение получения отчёта | 48 часов |
| Первичная оценка (severity + scope) | 5 рабочих дней |
| Патч для CRITICAL / HIGH | 14 календарных дней |
| Патч для MEDIUM / LOW | 60 календарных дней |
| Координированное публичное раскрытие | После выпуска патча, согласованно |

Если уязвимость подтверждена как CRITICAL и эксплуатируется в дикой
природе, мы можем сократить SLA-патча до 72 часов и временно
ограничить функциональность (через feature-flag или maintenance-mode).

## In scope

* `backend/` — FastAPI приложение, бот, фоновые задачи, alembic-миграции.
* `frontend/` — React TMA, Vite-сборка, WebSocket-клиент.
* `infra/` — `docker-compose.yml`, GitHub Actions workflows.
* `tests/` — фикстуры и логика, которая может скрывать реальную
  уязвимость в проде.
* Любые публично достижимые HTTP-/WebSocket-эндпоинты `*.example`
  деплоев и их превью на Vercel / Cloudflare.

## Out of scope

* Уязвимости в third-party зависимостях, не закрытые upstream —
  заводите issue в их треках и упомяните, что наш `pyproject.toml`
  / `package.json` импортирует уязвимую версию (мы подтянем bump,
  как только апстрим выпустит фикс).
* Уязвимости, требующие физического доступа к устройству пользователя.
* DoS, основанный на исчерпании bandwidth (rate-limiting у нас сделан
  через Redis-token-bucket; если вы нашли способ его обойти — это в
  scope, само-DoS — нет).
* Уведомления Sentry / Datadog о deprecation-warnings.

## Награды

Bug-bounty программы у проекта пока нет, но в публичном GitHub
Advisory мы перечислим всех репортеров с их согласия. Также готовы
выпустить именованную благодарность в `README.md` / `CHANGELOG.md`.

## Жизненный цикл advisory

1. Отчёт через приватный канал.
2. Подтверждение, классификация severity.
3. Приватный fix-бранч (`security/<short-id>`); PR не публикуется.
4. Деплой в production.
5. Публикация advisory (CVE при необходимости), благодарности
   репортеру.
