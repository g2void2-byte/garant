# Admin Panel — Functional Spec (draft for review)

Полный спек админ-панели для Garant TMA. Перед реализацией — твоё «ок/правки».

---

## 0. Подход

**Где живёт админка:** отдельный раздел внутри того же TMA — путь `/admin`, виден только если `is_admin=true` или `is_moderator=true` (видимость секций зависит от роли). Использует тот же дизайн Continental, тот же бэкенд, тот же PIN-auth.

**Альтернатива (опционально, скажи если надо):** отдельное web-приложение вне Telegram (логин email+password+2FA), доступное с десктопа без бота. Можно сделать в дополнение к встроенному `/admin`.

**RBAC-роли:**
- `admin` (level 5) — полный доступ ко всему, единственный кто может назначать других админов
- `moderator` (level 4) — read-only к финансам, может банить контент/комменты/услуги, читать чаты сделок, не может трогать балансы/выводы/комиссии
- `arbiter` (level 3) — только арбитражные дела (где он назначен) + чаты по ним
- `regular` (level 0) — нет доступа к `/admin` вообще

Существующие колонки `is_admin`, `is_moderator`, `is_arbiter` уже есть в `User` — буду их использовать.

**Аудит-лог:** каждое admin-действие пишется в новую таблицу `admin_audit_log` (actor_id, action, target_type, target_id, payload_json, reason, created_at, ip). Все денежные/деструктивные операции **требуют поля «причина»**.

## 1. Глобальные настройки платформы

Страница `/admin/settings`. **Только admin.**

- **Комиссии:**
  - Базовая комиссия с продавца (%) и с покупателя (%)
  - Минимальная комиссия в USD (округление вверх)
  - Override-комиссии по конкретным юзерам/категориям (whitelist пониженной ставки)
  - VIP-ставка для users с `deals_success >= N`
- **Лимиты сделок:**
  - Min/max сумма сделки (в USD-эквиваленте) глобально
  - Лимит количества активных сделок на одного юзера
  - Лимит количества создаваемых услуг на юзера
- **Лимиты кошелька:**
  - Min withdrawal по каждой валюте
  - Max withdrawal в сутки (если нужно)
  - Min deposit
  - Hold-период перед автоподтверждением депозита
- **Валюты:**
  - Включить/выключить TRX/BNB/USDT/DOGE/USDC/LTC/TON/BTC/ETH/SOL (флаг `is_enabled` на таблице currencies)
  - Установить курс fallback в USD (если CryptoBot недоступен)
  - Иконка/decimals/min_send для каждой
- **Тайм-ауты сделок:**
  - Авто-истечение сделки в `pending_confirmation` (часов)
  - Окно подачи арбитража после `in_progress` (часов/дней)
  - Авто-завершение after-arbitration cooldown
- **Тексты и шаблоны:**
  - Welcome-сообщение бота (Markdown)
  - Текст PIN-reset DM
  - Текст уведомления о новом депозите
  - Текст уведомления о новой сделке
  - Все тексты редактируются через UI, без redeploy
- **Feature flags:**
  - Включить/выключить регистрацию новых пользователей
  - Включить/выключить создание новых сделок
  - Включить/выключить создание новых услуг
  - Maintenance mode (показывает баннер «технические работы»)
  - Включить/выключить комментарии к услугам
  - Включить/выключить чат внутри сделки

## 2. Управление пользователями

Страница `/admin/users`. **Admin + Moderator** (Moderator не видит балансы/PIN).

- **Список юзеров с поиском:** по @username, по tg_user_id, по email (если будет), по диапазону регистрации, по роли, по статусу (active/banned/frozen)
- **Фильтры:** только админы, только модераторы, только арбитры, забанные, замороженные, с балансом >= X
- **Сортировки:** по дате регистрации, рейтингу, количеству сделок, общему депозиту
- **Профиль юзера (детальная страница `/admin/users/:id`):**
  - Всё что в открытом профиле + `tg_user_id`, дата регистрации, IP последнего захода (если логируем), активные сессии
  - **Финансы:** баланс по каждой валюте, общий депозит за всё время, общий вывод, кол-во депозитов/выводов, история транзакций (с пагинацией)
  - **Сделки:** все сделки (как buyer и как seller), фильтр по статусу
  - **Услуги:** все услуги юзера, активные/приостановленные/удалённые
  - **Отзывы:** оставленные ему + им оставленные
  - **Логи действий:** последние 100 действий (вошёл, создал сделку, и т.д.)
- **Действия с юзером:**
  - **Бан** (мягкий) — `is_banned=true`, причина обязательна. Бан запрещает: создавать сделки, услуги, выводить средства. Юзер видит баннер с причиной.
  - **Разбан**
  - **Заморозка баланса** — `is_frozen=true`, юзер не может выводить и тратить, причина обязательна. Депозиты разрешены.
  - **Разморозка**
  - **Принудительный сброс PIN** — обнуляет `pin_hash`, юзер обязан задать новый при следующем входе. Уведомление в DM.
  - **Принудительный сброс сессии** — инвалидирует все активные PIN-токены и WS-соединения.
  - **Назначить роль:** admin/moderator/arbiter/none. Только **admin** может назначить admin.
  - **Установить рейтинг вручную** — миграция/корректировка, причина обязательна.
  - **Сменить @username** — если Telegram это позволяет (вообще-то username в Telegram редактируется юзером, мы можем только обновить кэш).
  - **Принудительно скрыть профиль** — `is_hidden_profile=true`.
  - **Мягкое удаление** — `is_deleted=true`, все услуги уходят в архив, активные сделки требуют разрешения, причина обязательна.
  - **Полное удаление** — только admin, требует подтверждения, удаляет все строки кроме audit-log (юр. требование).
- **Bulk-операции:**
  - Массовый бан по списку tg_id (CSV)
  - Массовое уведомление выделенным юзерам

## 3. Управление ролями

Страница `/admin/roles`. **Только admin.**

- **Списки:** админы, модераторы, арбитры — три таблицы
- **Добавить роль:** по @username / tg_id. Можно с истечением (например, гостевой модератор на 30 дней).
- **Снять роль**
- **История изменений:** кто кого когда назначил/снял
- **Перечень полномочий каждой роли** прямо на странице (документация)

---

## 4. Управление сделками

Страница `/admin/deals`. **Admin + Moderator** (Moderator не может выполнять денежные действия).

- **Список с фильтрами:** по статусу, валюте, диапазону суммы, по buyer/seller (search), по дате создания, с открытым арбитражем, с запросом отмены, просроченные
- **Сортировки:** по дате, по сумме (USD-equivalent), по статусу
- **Детальная страница сделки `/admin/deals/:id`:**
  - Всё видимое + комиссия (%, value), buyer/seller balance snapshot на момент создания
  - Полная история событий (created, accepted, in_progress, completed, cancelled, arbitration_requested, arbiter_assigned, и т.д.) с timestamp
  - Полная переписка buyer ↔ seller (с medias)
- **Admin-действия:**
  - Принудительное завершение в пользу seller (release funds)
  - Принудительная отмена + refund buyer
  - Сплит-выплата (X% seller, Y% buyer)
  - Принудительная разморозка (если средства зависли из-за бага)
  - Удаление сделки (мягкое, только если pending_confirmation и обе стороны не возражают)
  - Открыть арбитраж от имени админа
  - Назначить арбитра вручную
- Все денежные действия → audit-log + DM обеим сторонам с причиной.

---

## 5. Арбитраж

Страница `/admin/arbitration`. **Admin + Arbiter** (Arbiter видит только свои дела).

- **Список открытых арбитражей:** новые без арбитра, в работе, ожидают решения, закрытые
- **Очередь без арбитра:** одна кнопка «Взять в работу» → назначает текущего арбитра на дело
- **Детальная страница арбитража:** вся переписка сделки + поля от buyer/seller (их версии конфликта) + загруженные доказательства (медиа)
- **Действия арбитра:**
  - Решить в пользу seller (release)
  - Решить в пользу buyer (refund)
  - Сплит (X% / Y%)
  - Запросить дополнительные доказательства (поле для текстового запроса → DM сторонам)
  - Эскалировать до admin (передать на ревью)
- **Метрики арбитров:** среднее время до решения, % решений в пользу buyer/seller, кол-во эскалаций — для оценки качества

---

## 6. Модерация услуг

Страница `/admin/services`. **Admin + Moderator.**

- **Список услуг с фильтрами:** по категории, владельцу, статусу (active/paused/banned/deleted), с жалобами
- **Действия:**
  - Принудительная пауза/активация
  - Бан услуги — `is_banned=true` + причина → DM владельцу
  - Удаление услуги (мягкое)
  - Модерация описания — редактирование (удаление запрещённого контента) с пометкой «отредактировано модератором»
  - Принудительное удаление комментариев/отзывов под услугой
- **Очередь жалоб** — если будет фича «пожаловаться на услугу», тут собирается, со счётчиком

---

## 7. Управление кошельками и балансами

Страница `/admin/wallets`. **Только admin.**

- **Просмотр баланса любого юзера** по всем валютам — поиск по @username/tg_id
- **Ручная корректировка баланса:**
  - Кредит (увеличить баланс) — причина + ссылка на сделку/тикет
  - Дебет (уменьшить баланс) — причина обязательна
  - Все ручные правки записываются как `WalletTransaction(kind="admin_adjustment")` + audit-log
- **Системные счета (treasury):**
  - Просмотр баланса комиссий, накопленных платформой
  - Возможность вывода комиссий на внешний адрес (с двойным подтверждением + 2FA)
- **Снимок балансов на дату** — для отчётов

---

## 8. Депозиты и выводы

Страницы `/admin/deposits` и `/admin/withdrawals`. **Только admin.**

- **Депозиты:**
  - Список всех CryptoBot invoices: pending/paid/expired/failed
  - Фильтры по юзеру, валюте, диапазону суммы, диапазону дат
  - Действия: ручное помечание paid (если webhook не прошёл), принудительный refund (с причиной)
  - Просмотр CryptoBot invoice_id + ссылка на их dashboard
- **Выводы:**
  - Очередь pending withdrawals (если в проде ручное подтверждение)
  - Approve / Reject (с причиной) → DM юзеру
  - Просмотр TX-hash отправки (если уже на блокчейне)
  - Принудительный retry, если CryptoBot вернул ошибку
  - Возможность отменить и вернуть на баланс
- **Сводка движения средств:** in/out по валютам за период

## 9. Рассылки и уведомления

Страница `/admin/broadcasts`. **Только admin.**

- **Создать рассылку:**
  - Аудитория: все / по фильтру (роль, диапазон регистрации, активность за период)
  - Тип: in-app notification, Telegram DM (через бота), оба
  - Заголовок + тело (Markdown)
  - Опциональная deep-link кнопка (на услугу/сделку/раздел)
  - Запланировать на дату/время или отправить сейчас
- **История рассылок:** статус, кол-во доставлено / прочитано / провалено
- **Шаблоны системных уведомлений** — редактируемые тексты автоматических уведомлений (см. секцию 1)

## 10. Модерация контента

Страница `/admin/moderation`. **Admin + Moderator.**

- **Очередь:** последние комментарии, отзывы, deal-сообщения
- **Действия:**
  - Удалить комментарий + предупредить автора (DM с причиной)
  - Удалить отзыв (только при злоупотреблении — оскорбления, спам)
  - Удалить deal-сообщение (внутрисделочный чат) — редкий случай (CSAM, угрозы)
  - Жёсткий бан автора (см. секцию 2)
- **Фильтр по ключевым словам / regex** — авто-флаг подозрительного контента в очередь

## 11. Аналитика / Dashboard

Страница `/admin/dashboard` (стартовая для админа). **Admin + Moderator** (Moderator видит без денежных метрик).

- **KPI-карточки (сверху):**
  - DAU / WAU / MAU
  - Новых пользователей за сегодня / неделю / месяц
  - Сделок за период (count + sum в USD)
  - Комиссий заработано за период (USD)
  - Открытых арбитражей сейчас
  - Очередь pending withdrawals
- **Графики:**
  - Объём сделок по дням за последние 30 дней
  - Регистрации по дням
  - Депозиты vs Выводы по дням
  - Топ валюты по объёму
- **Топ-листы:**
  - Топ-10 продавцов по обороту
  - Топ-10 покупателей по обороту
  - Топ-арбитры по количеству дел
- **Сегментация:**
  - Conversion: регистрация → первая сделка
  - Retention: D1 / D7 / D30
- **Экспорт:** CSV / Excel за любой период

## 12. Аудит и безопасность

Страница `/admin/audit`. **Admin + Moderator** (Moderator только свои действия).

- **Audit log** всех admin-действий: actor, action, target, причина, payload_diff, ip, timestamp
- **Фильтры:** по actor, по action_type, по target_type, по диапазону дат
- **Активные сессии:** список всех живых PIN-токенов с tg_user_id, last_activity, ip
- **Инвалидация сессии** одной кнопкой
- **Блок-листы:** забанные IP, забанные tg_user_id (отдельно от user-bans, на уровне rate-limiter)
- **Rate-limit overrides:** настройка лимитов API/PIN-попыток per role
- **2FA для админов** (опционально) — обязать TOTP при `/admin/*` логине

## 13. Управление ботом и системой

Страница `/admin/system`. **Только admin.**

- **Состояние сервисов:** статус Postgres, Redis, CryptoBot API, Telegram Bot API — health-check с лагом ответа
- **Размер очередей:** WS pub/sub, отложенные DM, фоновые задачи
- **Последние ошибки** (из логов backend) — top 20 stacktraces
- **Действия:**
  - Очистить кэш Redis
  - Переустановить webhook бота (если URL изменился)
  - Перегенерировать service-token (для CryptoBot интеграции)
  - Просмотр текущей конфигурации (read-only `.env` без секретов)
- **Резервные копии:** триггер на бэкап БД (если будет S3-интеграция)

## 15. Чёрные списки и анти-фрод

Страница `/admin/blocklist`. **Только admin.**

- **Блок tg_user_id** — без создания User-записи (preventive ban)
- **Блок IP** (если будем логировать IP)
- **Блок шаблонов имён** (regex)
- **Whitelist** — иммунитет от авто-бана для конкретных юзеров
- **Авто-эвристики** (опционально, на будущее):
  - Авто-флаг при >N сделок с одним и тем же контрагентом за час
  - Авто-флаг при отмене >N сделок подряд
  - Авто-флаг при попытке вывода всего баланса сразу после депозита

## 16. План реализации (стек PR'ов)

Если ты ок со скоупом — разбиваю на 4–5 PR'ов:

- **PR-A (foundation, ~1-2 дня):** Backend RBAC-middleware (`require_admin` / `require_moderator`), `admin_audit_log` таблица + миграция, базовая `/admin` shell-страница с навигацией, dashboard со счётчиками (KPI), список пользователей с поиском и базовыми действиями (бан/разбан, назначить роль). Это уже даёт MVP-админку.

- **PR-B (deals + arbitration + content, ~2 дня):** Управление сделками (просмотр, force-cancel, force-complete, split), арбитраж workflow (взять в работу, решить, эскалировать), модерация услуг/комментариев/отзывов.

- **PR-C (finance, ~2 дня):** Управление кошельками, ручные корректировки балансов, depo/withdrawals queue, approve/reject withdrawals, treasury, отчёты.

- **PR-D (broadcasts + analytics, ~1-2 дня):** Рассылки, шаблоны уведомлений, аналитика-дашборд, экспорт CSV, графики.

- **PR-E (system + settings + taxonomy, ~1-2 дня):** Глобальные настройки (комиссии, лимиты, feature flags), управление валютами/категориями/форумами, system page (health-checks, audit log filters), 2FA для админов (опционально).

Всё в Continental-дизайне, всё с тестами, всё с CI green.
